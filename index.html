L'utilisateur choisit Ubuntu, Debian ou Alpine, en terminal web ou en bureau XFCE (noVNC). La machine se détruit à l'expiration. A Flask controller places each machine on the least loaded worker and drives it over SSH, with no Docker API exposed. The user picks Ubuntu, Debian or Alpine, as a web terminal or an XFCE desktop (noVNC). The machine destroys itself on expiry.
  • Reprise sur panneFailover Un worker silencieux passe hors ligne au bout d'environ 90 s et ses machines sont recréées sur un autre nœud, sans perdre la durée réservée. A silent worker goes offline after about 90 s and its machines are recreated on another node, without losing the reserved time.

Encrypted root password (Fernet) shown once, containers stripped of extra capabilities (--cap-drop ALL), CSRF protection, brute-force lockout, strict CSP.   • Ce que ça faitWhat it does Une seule chaîne du paquet à l'incident, pour le laboratoire, le rejeu de PCAP et la capture réelle (scapy). 52 caractéristiques de flux, deux étages de machine learning (anomalies entraînées sur du trafic bénin seul, puis un classifieur qui nomme la famille et peut opposer son veto), un seuil par hôte et des alertes regroupées en incidents. Console React/TypeScript en temps réel (FastAPI, WebSocket). A single pipeline from packet to incident, for the lab, PCAP replay and live capture (scapy). 52 flow features, two machine-learning stages (anomalies learned on benign traffic only, then a classifier that names the family and can veto), a per-host threshold, and alerts grouped into incidents. Real-time React/TypeScript console (FastAPI, WebSocket).

Since the scores were already close to uniform, I replaced it with a per-host quantile.

Networking project of the STI3A course at INSA CVL (October 2025 – April 2026), built by eleven students. It extends the Python game. Reference repository: YOUSSEF4315/STI3A-Projet_reseaux_1. My repository is a mirror: it keeps the full Git history and each author's rights.
  • Deux programmes par machineTwo programs per machine Chaque joueur lance le jeu et l'IA en Python, et un démon réseau en C. Ils se parlent en local par IPC ; seuls les démons dialoguent à travers le réseau, en pair-à-pair. Le programme Python n'a jamais conscience d'être en réseau. Each player runs the Python game and AI, and a C network daemon. They talk locally over IPC; only the daemons talk across the network, peer-to-peer. The Python program is never aware it is on a network.
  • Propriété réseauNetwork ownership Sans serveur, deux joueurs peuvent modifier la même unité en même temps. Règle retenue : une entité n'a qu'un seul propriétaire légitime à un instant donné, et pour agir sur une unité qu'il ne possède pas, un nœud négocie d'abord le transfert de propriété. With no server, two players can change the same unit at the same time. The rule: an entity has a single legitimate owner at any moment, and to act on a unit it doesn't own, a node first negotiates the transfer of ownership.
  • Deux versionsTwo versions Version 1 : diffusion « best-effort » sans garantie, d'où des unités en double, des « fantômes » et des états désynchronisés. Version 2 : réseau en C avec propriété réseau, anti-zombie, anti-désynchronisation, victoire synchronisée, délais d'attente et reprise après perte de paquets. Version 1: "best-effort" broadcast with no guarantee, hence duplicated units, "ghosts" and desynchronised states. Version 2: network layer in C with network ownership, anti-zombie, anti-desync, synchronised victory, timeouts and recovery after packet loss.
